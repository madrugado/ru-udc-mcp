# RuUDC-MCP

MCP-сервер для работы с **УДК** (универсальной десятичной классификацией):
поиск кодов, навигация по иерархии и подбор кода по тексту — прямо из агента в ZCode.
Работает локально (stdio) и как публичный remote MCP на Vercel — см. [Подключение](#подключение).

Сервер объединяет **два источника**:

| источник | что это | объём | статус/лицензия |
|---|---|---|---|
| `teacode` | Электронный справочник УДК [teacode.com/online/udc](http://teacode.com/online/udc/) — детальные русскоязычные таблицы, сгенерированные из метаописания в Dublin Core | ~126 000 кодов | снапшот с сайта (сайт не обновлялся примерно с 2015 г., основан на старых русских печатных таблицах); часть кодов помечена «исключён» |
| `summary` | Официальный **UDC Summary** (UDC Consortium) в русском переводе — сокращённые основные таблицы + вспомогательные определители | ~2 700 кодов | © UDC Consortium, CC BY-NC-ND 3.0 |

Они дополняют друг друга: `summary` — актуальный официальный каркас, `teacode` — глубина
(5–7 уровней) и русскоязычные формулировки, к которым привыкли ВАК/РИНЦ.

## Инструменты MCP

| инструмент | что делает |
|---|---|
| `udc_sources()` | список источников: объём, происхождение, дата снапшота, лицензия |
| `udc_search(query, source, limit)` | поиск: по префиксу кода (`621.39`) и по словам из заголовков (`нейронные сети`), с релевантностью |
| `udc_get(code, source)` | карточка кода: описание, примечания, перекрёстные ссылки, цепочка предков, прямые дети; составные коды (`621.372:004.9`) раскладываются на части |
| `udc_children(code, source, limit)` | прямые дочерние коды (один уровень вниз) |
| `udc_suggest(text, source, limit)` | подбор кодов УДК по свободному тексту (аннотация/тема статьи): IDF-взвешенное покрытие терминов, путь по иерархии, предупреждения об исключённых кодах |

Все ответы — JSON с `ok: true/false` и понятными сообщениями об ошибках.

## Запуск

Нужен Python 3.10+ и [uv](https://docs.astral.sh/uv/):

```bash
uv sync            # создаёт .venv и ставит зависимости (mcp>=2)
uv run python tests/smoke_test.py   # end-to-end тест всех инструментов
uv run server.py   # MCP-сервер поверх stdio
```

## Подключение

### Вариант 1: удалённый сервер (ничего устанавливать не нужно)

Сервер развёрнут на Vercel как публичный remote MCP — **Streamable HTTP**, stateless,
JSON-ответы:

```
https://ruudc-mcp.vercel.app/mcp
```

В клиенте с поддержкой remote MCP (ZCode, Claude Desktop и т.п.) добавьте в `mcp.servers`:

```json
{
  "mcp": {
    "servers": {
      "ruudc-remote": { "type": "http", "url": "https://ruudc-mcp.vercel.app/mcp" }
    }
  }
}
```

- ZCode: файл `~/.zcode/cli/config.json` (все проекты) или `.zcode/config.json`
  воркспейса; после правки перезапустите сессию — статус виден в Settings → MCP.
- Клиентам без поддержки remote MCP — мост-прокси: `npx mcp-remote https://ruudc-mcp.vercel.app/mcp`.

Endpoint публичный, данные read-only; холодный старт функции ~10–25 с (импорт 27 МБ
данных), тёплые ответы — доли секунды.

### Вариант 2: локально (stdio)

Нужны Python 3.10+ и [uv](https://docs.astral.sh/uv/):

```bash
git clone git@github.com:madrugado/ru-udc-mcp.git
cd ru-udc-mcp
uv sync    # создаёт .venv, ставит зависимости (mcp>=2); данные data/*.json уже в репо
```

и укажите сервер в конфиге клиента — ZCode: `~/.zcode/cli/config.json` (user-scope)
или `.zcode/config.json` воркспейса (workspace-scope):

```json
{
  "mcp": {
    "servers": {
      "ruudc": {
        "type": "stdio",
        "command": "uv",
        "args": ["--directory", "/путь/к/ru-udc-mcp", "run", "server.py"]
      }
    }
  }
}
```

После правки перезапустите сессию. Проверка без агента: `uv run python tests/smoke_test.py`.

## Удалённый сервер на Vercel (как задеплоен вариант 1)

«Вариант 1» — это этот же репозиторий, собранный как Vercel Function: `api/index.py`
оборачивает тот же `server.py` в Streamable HTTP (stateless, `json_response` — без
SSE-сессий, поэтому корректно работает в serverless).

- Деплой: `vercel deploy --prod` (нужен Vercel CLI и `VERCEL_TOKEN` в окружении;
  токен лежит в `~/.zshenv`, в репозитории его нет). `vercel.json` включает `data/**`
  и `server.py` в бандл (`includeFiles`) и назначает чистый путь `/mcp`.
- Endpoint публичный (Deployment Protection отключена через API), данные read-only.
- Особенности платформы (новый Python-пайплайн Vercel с uv/`uv.lock`): строится ровно
  одна функция-приложение (`api/index.py`), прочие `api/*.py` не маршрутизируются; при
  internal rewrite функция видит путь-назначение (`/api/index.py`), поэтому проверка
  живости — POST `initialize` на `/mcp`, а DNS-rebinding-защита SDK отключена явно
  (за прокси Vercel Host-заголовок — домен деплоя).


## Обновление данных

Данные лежат в `data/*.json` (снимки на дату из поля `meta.retrieved`):

```bash
python3 scripts/scrape_teacode.py --workers 8      # обход teacode.com, ~10-15 мин
python3 scripts/scrape_udcsummary.py               # официальный Summary, ~15 сек
```

Скрипты используют только stdlib и пишут JSON с метаданными (источник, дата,
лицензия, примечание об издании).

## Как это устроено

- `scripts/scrape_teacode.py` — волновой BFS-краулер статических страниц teacode
  (каждый узел — страница с таблицей дочерних кодов; листовые коды без ссылок,
  примечания и перекрёстные «см. X» сохраняются). Родительские связи
  канонизируются по длиннейшему префиксу кода.
- `scripts/scrape_udcsummary.py` — парсер `d.add(...)`-деревьев udcsummary.info;
  каждая секция отдаётся одной страницей, иерархия явная (nid/pid).
- `server.py` — MCPServer (официальный python-sdk, stdio; для Vercel `api/index.py`
  оборачивает тот же сервер в Streamable HTTP). При старте строит
  индексы: по коду, по родителю, нормализованные заголовки и IDF-веса терминов.
  Поиск/подсказка — лексический (токены с удалением стоп-слов, фразовые бонусы,
  приоритет более широких кодов при равной релевантности). Никакого сетевого
  доступа в рантайме — только локальные JSON.

## Сверка с другими русскоязычными источниками (2026-10)

Датасеты сверены с независимыми русскоязычными УДК-источниками: [ClassInform — «Классификатор УДК 2021»](https://classinform.ru/udk.html), [Triumph — «УДК Классификатор 2026»](https://www.triumph.ru/html/serv/udk.html), а также проверены [perviy-vestnik.ru/udc](https://perviy-vestnik.ru/udc/) и [digitalnauka.ru/udc](https://digitalnauka.ru/udc).

**Происхождение источников** (установлено при сверке):
- perviy-vestnik.ru/udc (виджет удк.xyz, API `udc-api.perviy-vestnik.ru`) — **копия данных teacode.com** (индекс совпадает дословно, включая переносы строк; религия — то же старое издание), несмотря на заявление «УДК 2023/2025, 436 442 кода» на лендинге;
- digitalnauka.ru/udc (`files/data.json` + fuse.js) — **копия официального UDC Summary**: 1913/1913 узлов совпадают с нашим summary-датасетом, близость заголовков 0.999 (вплоть до опечатки «Mедицинские»);
- ClassInform (2021) — усечённые таблицы (~3 уровня); Triumph (2026) — современная редакция с глубиной; оба независимы.

**Результаты сверки:**
- **Совпадение по общим кодам хорошее**: средняя близость заголовков teacode ↔ Summary 0.79; пробы (`004.9`, `519.2`, `616-006`, `004.032.26`, `004.056`, `621.372`) подтверждены всеми источниками дословно.
- **teacode действительно местами устарел**: 19% основных кодов актуального Summary в нём отсутствуют; ~12% общих кодов раскрыты радикально иначе. Это не опечатки, а реальные перестройки редакций: целиком раздел **2 «Религия»** (в teacode 22=«Библия», 27=«История христианской церкви»; в актуальной редакции 22=«Религии Дальнего Востока», 27=«Христианство» — подтверждено ClassInform и Triumph), **79** (791=«Кино», 793.3=«Танец»), **60** (→«Биотехнология»), 005, 659. Поэтому `udc_get` при расхождении источников выдаёт `warnings` с рекомендацией предпочесть `summary`.
- **Глубина**: ClassInform и digitalnauka — усечённые таблицы (~3 уровня, коды вроде `621.372`/`82-93` отсутствуют), так что как третий источник они не нужны; teacode остаётся единственным онлайн-источником такой глубины на русском (Triumph имеет глубину, но это динамическое дерево без массовой выгрузки).
- Известные дефекты самих источников: в русском Summary часть заголовков не переведена (616-71…78, 82-31/32, 81-112… — английские); у teacode запись `82-93` «Историческая литература для детей и юношества» сомнительна (общий определитель −93 — «издания для детей и юношества»).

## Ограничения

- Подсказка `udc_suggest` — лексическая эвристика, а не обученный классификатор:
  она выбирает заголовки с наибольшим покрытием терминов; финальный выбор уровня
  детализации и составление составного кода (`A:B`, `A+B`, определители) — за
  агентом/человеком.
- Данные teacode — снапшот 2026-10-03 со статичного сайта; новые коды УДК
  после ~2015 г. там отсутствуют (для актуальной топ-уровневой картины есть
  `summary`).
- Полные таблицы УДК проприетарны (UDC Consortium), поэтому сервер не включает
  их и не умеет валидировать произвольные составные коды на синтаксис.
